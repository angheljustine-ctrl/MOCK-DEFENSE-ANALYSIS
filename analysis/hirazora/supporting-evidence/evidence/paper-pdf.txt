INTRODUCTION  
HIRAZORA Studio Co. Inventory and Point of Sale System is a web -based system developed to help manage 
products, stocks, sales, receipts, and other store -related records in one place. Th e system was created to make 
daily store operations more organized and easier to manage compared to manually checking products and 
recording transactions. 
The system helps users monitor available stocks, manage product information, record sales, process transactions 
through the Point of Sale, and review sales reports. It also includes user accounts with different access levels for 
Admin, Manager, and Cashier so that each user can only access the functions related to their role.  
JavaScript is mainly used t o make the system interactive and functional. It handles form validation, product and 
inventory updates, searching and filtering, sales transactions, calculations, reports, user interaction, and storing 
data using Local Storage and Session Storage.  
The sys tem is designed for HIRAZORA Studio Co. and can be used by the Admin, Manager, and Cashier 
depending on their assigned responsibilities. Its main purpose is to make product, inventory, and sales 
management faster, more organized, and easier to monitor.

PROJECT OVERVIEW 
2.1 System Name  
HIRAZORA Studio Co. Inventory and Point of Sale System  
2.2 System Description  
HIRAZORA Studio Co. Inventory and Point of Sale System is a web-based system designed to manage the store’s 
products, inventory, sales, receipts, users, reports, backups, and system settings.  
The system allows authorized users to perform different tasks based on their assigned role. The Admin has full 
access to the system, the Manager can handle most store operations, while the Cashier mainly focuses on Point of 
Sale and sales-related functions. 
JavaScript is used to control the system’s main functions such as adding and updating records, validating forms, 
searching and filtering data, calculating sales, updating stocks, generating reports, and managing stored data using 
Local Storage and Session Storage. 
The system also includes barcode support, user authentication, role -based access, backup and restore functions, 
and configurable settings to help make store operations easier and more orga nized. 
2.3 Problem Statement 
Managing products, stocks, and sales manually can take more time and may result in inaccurate records. It can 
also be difficult to monitor current stock levels, track sales transactions, and identify which products are low in 
stock or already out of stock.  
Another problem is that different store users may need different levels of access. Without proper user roles, all 
users may be able to access functions that are not related to their responsibilities.  
HIRAZORA Studio Co. needs a system that can organize product information, monitor inventory changes, record 
sales transactions, manage user access, and provide reports in one platform.

PROJECT LIMITATIONS 
The HIRAZORA Studio Co. Inventory and Point of Sale System has limitations based on the current technology, 
system scope, and intended use of the project. These limitations define the functions that are not included in the 
final version of the system. 
 The system is designed for web browser use only and does not include a dedicated mobile application . 
 The system uses Local Storage and Session Storage  for storing sy stem records and login sessions. 
Because of this, data is mainly available on the browser and device where the system is used . 
 The current version does not use a centralized online database or cloud -based storage, so data is not 
automatically synchronized between different computers or devices . 
 Automatic scheduled backups cannot run when the browser or system is closed. Backup reminders and 
backup operations require the system to be active.  
 Some features are restricted according to user roles. For example, User Management is limited to Admin 
users, while backup restoration is also restricted to the Admin for security purposes . 
 The system depends on the browser environment, so clearing browser storage may affect locally stored 
records if a backup has not been created. 
 The project focuses on inventory, Point of Sale, sales, receipts, reports, user management, backup, and 
system settings. Other business functions such as accounting, supplier management, online ordering, and 
employee payroll are outside the curre nt scope. 
 Real email or SMS notifications are not included. Notification settings are limited to functions that can be 
handled within the current system.

9.3 System Flow 
The system begins when a registered user logs in using valid account credentials. After login, the system checks 
the user's role and provides access to the appropriate modules. The Admin has full access, the Manager handles 
most operational functions, while the Cashier mainly works with POS and sales-related tasks. 
Products and categories are managed through their respective modules, while inventory keeps track of stock 
quantities and stock movements. During a POS transaction, selected products are added to the cart and the system 
calculates the transaction total. Once the sale is completed, the sales record is saved and the product stock is 
updated. 
Sales and receipts can then be reviewed through the Sales module, while the Reports module summarizes 
information from products, inventory, and s ales records. The Backup and Security module provides tools for 
protecting system data, and the Settings module stores preferences used by the system. Users can continue 
working with the available modules or log out when their tasks are completed.

CONCLUSION 
The HIRAZORA Studio Co. Inventory and Point of Sale System was successfully developed as a complete web -
based system for managing the major operations of the store. The final system combines user authentication, role-
based access, product and category manageme nt, inventory monitoring, barcode integration, Point of Sale, sales 
and receipts, refund processing, reports, backup and restore, security functions, and system settings in one 
organized platform. 
The system was designed to improve the way HIRAZORA Studio Co. handles products, stocks, transactions, and 
user responsibilities. Through the use of Admin, Manager, and Cashier accounts, each user is given access only 
to the modules related to their role. This helps maintain proper control of the system while allowing daily tasks to 
be completed in a more organized and efficient manner.  
JavaScript serves as one of the main technologies used in the system. It is responsible for important functions 
such as form validation, searching, filtering, pagination, calculations, product and stock updates, sales processing, 
receipt handling, dynamic page content, session behavior, and interaction with Local Storage and Session Storage. 
These functions allow the system to respond to user actions and keep the different modules connected with each 
other. 
The final outcome of the project demonstrates how HTML, CSS, JavaScript, PHP pages, and browser -based 
storage can be combined to create a functional Inventory and Point of Sale System. The development of the project 
also provided practical experience in designing user interfaces, managing data, implementing user permissions, 
connecting multiple system modules, and testing how each function works as part of one complete system.  
Overall, the HIRAZORA Studio Co. Inventory and  Point of Sale System achieved the main goal and objectives 
of the project by providing a centralized platform for managing the store’s products, inventory, sales, users, 
reports, backups, and system preferences. The final system provides a practical solut ion for the current needs of 
HIRAZORA Studio Co. while also providing a foundation that can be improved in the future.  
Future improvements may include the use of a centralized database, cloud -based synchronization, real email or 
SMS notifications, two-factor authentication, and a dedicated mobile application. These improvements can further 
increase the security, accessibility, and capability of the system while maintaining the functions already provided 
by the final version.
