P0017 INTRODUCTION
P0019 The Doughnut Disturb Overall Management System is a browser based management system developed to support the daily operations of a doughnut business. It brings important business activities into one system, including employee records, attendance, payroll, leave, products and inventory, reports, administrator accounts, and system settings.
P0020 The system was developed to provide a more organized way of managing business records and routine administrative tasks. Instead of keeping information in separate manual records, the system provides connected pages where authorized users can view, add, update, and manage information.
P0021 JavaScript is used as the main programming language for the system behavior. It handles interactive forms, validation, calculations, dynamic page content, notifications, role based behavior, and browser storage. The project demonstrates how JavaScript can be used together with HTML and CSS to create an interactive management application.
P0022 The main users are administrators and crew members. Administrators are given management functions, while crew access is limited according to the supported role behavior of the system.
P0024 PROJECT OVERVIEW
P0026 System Name: Doughnut Disturb 
P0027 System Type: Browser based business management system
P0028 Technology: HTML, CSS, and JavaScript
P0029 Storage: Browser localStorage and sessionStorage
P0030 System Description: The system is designed to centralize common management activities of Doughnut Disturb Co. It provides separate modules for employee management, attendance, payroll, leave, products and inventory, reports, administrator management, account creation, and system information.
P0031 Problem Statement:
P0032 Business information can become difficult to organize when employee records, attendance, payroll, inventory, and administrative information are handled separately. Manual or unconnected records can also make it harder to monitor current information and prepare management reports.
P0033 Proposed Solution:
P0034 The proposed system provides one browser based platform where authorized users can access related management modules. The dashboard provides an overview, while individual pages handle specific business functions. JavaScript connects the page behavior, calculations, validation, and browser based data storage.

P0074 PROJECT LIMITATIONS
P0076 The supplied project is a frontend prototype. Its current storage and security design are suitable for demonstration and development, but they should not be treated as a production business system.
P0077 There is no backend server or real database.
P0078 Records are stored in browser localStorage, so they are limited to the browser environment.
P0079 Authentication and authorization are handled on the frontend and are not server secured.
P0080 Passwords are not protected by production level server side password hashing.
P0081 There is no complete server side role based access control.
P0082 There are no full server side audit logs or secure session controls.
P0083 The current payroll assumptions should be replaced with the actual company payroll policy beforereal deployment.
P0084 Advanced approval workflows and detailed inventory transaction history are not fully implemented.
P0085 The project does not provide a native mobile application.
P0086 Future improvements should include a secure backend and API, a real database, server side authorization, audit logs, employee document support, approval workflows, payslip export, inventory transaction history, reporting export, database integrity controls, and backup and restore functions.

P0182 System flow
P0184 The Doughnut Disturb Overall Management System starts when the user opens the system and accesses the login page. The user enters their username or email and password. After successful login, the system verifies the account and allows the user to access the dashboard based on their assigned role.
P0185 From the dashboard, the user can select the different modules available in the system. The Admin can manage employee records, attendance, leave requests, payroll, products and inventory, reports, and administrator accounts. The user can add, update, search, and view information depending on the available functions and permissions.
P0187 For employee management, the Admin can create and maintain employee records. The employee information is then used by other modules such as attendance and payroll. In the Attendance module, the Admin can record time in and time out, monitor present, absent, late, and overtime records, and review attendance information.
P0188 The Payroll module uses employee and attendance information to help calculate payroll. The system records basic salary, working days, overtime, allowances, deductions, gross pay, net pay, and payroll status. The Leave module is used to manage employee leave records, while the Products and Inventory module allows the Admin to monitor products and stock information.
P0189 The Reports module gathers information from the system and presents management reports based on available employee, attendance, leave, and payroll records. The Admin can also manage system accounts through the Admin Management and Create Account modules.
P0190 After the user completes the required task, the changes are saved in the system's browser storage and can be reflected in the appropriate modules. The user can then continue to another task or log out of the system. This completes the system flow from login, data management, processing, reporting, and logout.

P0221 CONCLUSION
P0222 The Doughnut Disturb Overall Management System provides an integrated browser based management workflow using HTML, CSS, and JavaScript. The project includes authentication, dashboard monitoring, employee management, attendance, payroll, products and inventory, leave, reports, administrator accounts, and settings.
P0223 JavaScript is central to the system because it controls interactive forms, validation, calculations, dynamic content, role based behavior, notifications, and browser based data synchronization.
P0224 The supplied system files show implemented functions such as automatic employee IDs, attendance calculations, standardized payroll fields, duplicate prevention, employee archival, role restrictions, profile and password updates, product validation, notifications, and synchronized page updates.
P0225 The main limitation is that the current project is a frontend prototype that uses browser storage. For actual business deployment, authentication, authorization, validation, and data operations should be moved to a secure backend and real database. Other future improvements include approval workflows, audit logs, payslip export, inventory transaction history, database integrity, and backup and restore.
P0226 Overall, the project demonstrates how JavaScript can be used to build an interactive management system while documenting the technical limitations that should be addressed before production deployment.
